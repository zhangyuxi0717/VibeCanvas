# 小范围试用：范围、额度与验收记录

这份文档回答三个问题：给谁用、能用多少、我验证过什么、还差什么。

## 1. 试用范围

| 项目 | 当前设定 | 配置项 |
| --- | --- | --- |
| 试用人数上限 | 10 | `TRIAL_MAX_USERS` |
| 谁可以登录 | 名单内的邮箱 | `TRIAL_ALLOWED_EMAILS`（逗号分隔） |
| 名单为空时 | 默认拒绝所有人 | 只有显式设 `TRIAL_OPEN=true` 才放开，生产环境不建议 |
| 文字生成（全站） | 每天 1000 次 | `GENERATE_DAILY_LIMIT` |
| 文字生成（每人） | 每天 50 次 | `GENERATE_PER_USER_DAILY_LIMIT` |
| 配图（全站） | 每天 20 张 | `IMAGE_DAILY_LIMIT` |
| 配图（每人） | 每天 15 张 | `IMAGE_PER_USER_DAILY_LIMIT` |
| 配图频率 | 每人每分钟 5 次 | `IMAGE_PER_MINUTE` |
| 配图并发 / 排队 | 同时 2 个，最多 20 个排队 | `IMAGE_MAX_CONCURRENT` / `IMAGE_QUEUE_LIMIT` |

说明：

- 人数上限靠「名单长度 ≤ `TRIAL_MAX_USERS`」在启动时校验；名单之外的人登录后调接口会被拒。
- 配图按张计费：一次「AI 配图」生成三张，扣三次个人额度。所以「每人每天 15 张」= 每天最多 5 次配图。
- 全站配图额度 20 张是为试用期设的硬闸，防止密钥被意外刷光；需要更多时改 `.env` 后重启。
- 文字额度计数在内存里，重启服务会清零；配图额度写在 `data/image-tasks.json`，重启不清零。
- 停掉付费请求的总开关是 `GENERATE_SERVICE_ENABLED=false` 和 `IMAGE_SERVICE_ENABLED=false`。

## 4. 已知限制

按「会不会影响试用」排序：

1. **没有云端时，作品只在用户自己的浏览器里。** 换设备、换浏览器、清缓存都会看不到；
   换端口也算换站点。试用期间请让用户固定用同一个地址。
2. **文字生成额度存在内存里。** 重启服务后所有用户的当日文字额度会清零。
   配图额度不受影响（落盘）。试用期人数少，影响可控，但不要让用户发现「重启就能刷额度」。
3. **配图任务与图片在 30 分钟后自动清理。** 用户关掉页面再回来，看不到之前的配图任务。
   已经导出或保存进作品里的图片不受影响（那是浏览器里的 Blob）。
4. **登录过期只在服务端验证过。** 401 的返回和提示有测试覆盖，但没有在真实 Supabase 上
   等到会话自然过期再点一次按钮；首次真实试用时请留意。
5. **云端同步、云端备份恢复未对真实 Supabase 执行过。** 见 `docs/DEPLOY.md` 第 7.2 节。
6. **单进程。** 不支持多实例水平扩展：额度计数、任务队列都在进程内存里。10 人试用够用。
7. **配图提示词是英文。** 本地 SDXL 类模型读不懂中文，服务端会先翻译成英文再生成；
   翻译失败时退回中文并在界面上提示结果可能不符。
8. **没有自动重试。** 模型超时或失败后需要用户手动点重试（避免重复计费）；
   图片状态为 `uncertain` 时不会自动重发。

## 5. 试用期间每天看什么

```bash
# 今天的生成/配图/导出次数（按事件名统计）
grep -o '"name":"[a-z_]*"' data/events/events-$(date -u +%F).jsonl | sort | uniq -c

# 失败情况
grep '"name":"generate_fail"\|"name":"image_fail"' data/events/events-$(date -u +%F).jsonl

# 用户反馈
cat data/feedback/feedback-$(date -u +%F).jsonl

# 服务是否健康
curl -s https://你的域名/readyz
```

事件里没有正文和照片；反馈是用户主动写的那几句，最多 300 字。

判断是否要继续放人的信号：`generate_fail` 里 `errorKind=timeout` 占比高 → 模型服务慢；
`errorKind=quota` 多 → 额度设小了；`image_fail` 多 → 配图服务和提示词需要调。

## 6. 不花钱的临时对外方式（Cloudflare 临时隧道）

适合两三个人看、当天就要能打开的情况。已在 2026-10-30 实际跑通过一次。

```bash
npm run build
PORT=8080 npm run trial   # 起隧道 + 用生产配置起服务，打印一个 https 地址
```

脚本会做三件事：开隧道拿地址 → 用该地址作为 `APP_ORIGIN` 启动服务 → 同时监听 Ctrl+C。
服务本身只监听 `127.0.0.1`，外部只能通过隧道进来。`PORT` 不写就默认 3000，被占用时会报
`EADDRINUSE` 并自动关掉隧道（本机 3000 当时被另一个 node 进程占着，所以这次用了 8080）。

`cloudflared` 放在 `C:\tmp\cloudflared\cloudflared.exe`，也可以用 `CLOUDFLARED=<路径>` 指定。
这个文件是从 `ghfast.top` 镜像下的，运行前做过签名校验：

```
Status=Valid
Signer=CN="Cloudflare, Inc.", O="Cloudflare, Inc.", C=US
Issuer=CN=DigiCert Trusted G4 Code Signing RSA4096 SHA384 2021 CA1
SHA256=D521B3BF68982165F0D06D76732F22D9A105EF057FF3AE4C0986F3A23190950F
```

复核命令：`powershell -NoProfile -Command "(Get-AuthenticodeSignature 'C:\tmp\cloudflared\cloudflared.exe').Status"`，
输出必须是 `Valid`。

### 6.2 必须先知道的五件事

1. **地址每次重启都会变**（这次是 `ascii-substances-fighting-adaptor.trycloudflare.com`，
   重开一次就换了一个）。浏览器作品是按地址隔离的，换地址后用户看不到之前的作品。
   要固定地址，需要自有域名 + 命名隧道（Cloudflare 免费账号也支持），这就要买域名了。
2. **电脑不能关机、不能睡眠。** 睡眠后隧道断开，地址作废。
3. **没有登录就没有名单。** 没配 Supabase 时无法按邮箱限制，拿到链接的人都能用；
   实际约束是额度上限和随机链接。建议把 `GENERATE_DAILY_LIMIT`、`IMAGE_DAILY_LIMIT` 调小，
   并把链接只发给受邀的人。
4. **内地网络到 `trycloudflare.com` 可能不稳。** 上面测的是本机出口，试用用户走自己的网络；
   先自己用手机流量打开一次，打不开就换方案，别等用户反馈。
5. **「AI 配图」跑的是这台电脑上的 ComfyUI。** 试用时有人点配图，会占用你的显卡几十秒，
   同时隧道开着时任何人都能触发（受 `IMAGE_DAILY_LIMIT=20`、并发 2 限制）。不想被占用就把
   `IMAGE_SERVICE_ENABLED=false` 传给 `npm run trial`。

`trycloudflare.com` 是 Cloudflare 给临时测试用的地址，没有可用性承诺；长期用还是要走到第 7 节。

## 7. 正式放人之前还需要你做的

1. 买服务器、域名（需要备案的话先备案）——见 `docs/DEPLOY.md` 第 2 节，费用需要你确认；
2. 决定是否启用 Supabase 账号与云同步；启用的话在空项目上先跑一遍备份 → 恢复；
3. 准备一句给试用用户的话，说明「作品只存在当前浏览器」这件事；
4. 确定试用名单（邮箱），填进 `TRIAL_ALLOWED_EMAILS`，数量不超过 `TRIAL_MAX_USERS`；
5. 决定每天愿意为配图花多少钱，据此调 `IMAGE_DAILY_LIMIT`。
